# Tenancy (slice 4 of #776) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** Wirebench Server becomes multi-tenant. A `tenants` table, `tenant_id` on every table, forced row-level
security, tenant resolution by `Host`, per-tenant directories and data keys, the six guards of §5.4, the host-instance
lease and the self-hosted migration. A self-hosted installation stays one tenant, and nobody using it can tell.

**Architecture:** Five parts, one pull request each, in dependency order.

- **Part A** adds the tenants and the column:
  - a test database role that cannot bypass row-level security;
  - a fixture database at `0019`;
  - migration `0020`;
  - `src/tenancy/` (scope, tenant database, directory, job loop);
  - resolution by `Host`.
- **Part B** puts the first half of the modules in a tenant: identity, teams and licensing, sync, hooks and CI tokens,
  live and terminal shares.
- **Part C** puts the second half of the modules in a tenant, then forces row-level security:
  - scheduled runs, audit, SSO, session logs, the agent, the host module and the admin command line;
  - migration `0021`, the scope gate and the isolation suite.
- **Part D** builds the per-tenant directories and data keys: the layout, the file step, the wrapped data key and the
  re-wrap.
- **Part E** builds the lease, the cap and the way back: `host_leases` in use, the instance cap, `admin tenancy
  revert`, the e2e on a migrated server, and the docs.

**Tech Stack:** TypeScript (ESM), Fastify 5, `pg`, PostgreSQL 16 (15 at least) row-level security, `node:crypto`
(HKDF, AES-256-GCM), vitest, Playwright.

**Spec:** `docs/specs/2026-10-24-wirebench-hosted-edition-design.md` §3.5, §4, §5.3–§5.5, §13, §14 and §19 (which wins
where they differ); ADR-0032, ADR-0036; issue #ISSUE.

## Global Constraints

- **Invisible to self-hosted.** No route, response, page, command output or file that a self-hosted user or operator
  sees names a tenant or a slug. The only new operator surfaces are `admin tenancy check|status|revert` and a
  start-up warning about a bypassing role. Existing routes and channels keep their shapes.
- **Hosted mode is test-only.** `config check` refuses `WIREBENCH_SERVER_MODE=hosted` (spec §19.1). Tests build a
  hosted `ServerConfig` directly. Nothing of slices 5 to 8 is built: no signup, payment provider, wildcard name,
  `LISTEN`/`NOTIFY` or bypass role.
- **Row-level security is switched on last.** Parts A and B leave `tenant_id` with a constant default and no policy,
  so every task stays green while the modules move. `0021`, in Part C, forces the policies. Nothing merges in between
  that would break a self-hosted server.
- **Migrations** continue the global numbering: `0020` and `0021`, under `packages/server/migrations/tenancy/`. They
  are listed in `serve.ts`'s `allMigrations` beside the module folders. New server env vars follow the config
  checklist in `packages/server/src/config.ts`; slice 4 adds none an operator can set except `WIREBENCH_SERVER_MODE`.
- **Sealed audit rows are never updated** (`0012`'s rule). The column is added with a constant default, which only
  changes the catalog.
- **Gates:**
  - Commit after every task with `WIREBENCH_SKIP_PERF=1 pnpm check` green, and run `pnpm test:perf` before each push.
  - Run `eslint .` with `NODE_OPTIONS=--max-old-space-size=8192` and the worktree ignore patterns.
  - Server integration tests need PostgreSQL (`packages/server/compose.yaml`), connected as the non-superuser role of
    Task 1.
- **House rules:**
  - No local Electron e2e windows; CI runs e2e.
  - Commit as Mohammed Naami, with no trailers.
  - Never name a product that inspired a feature.
  - Never let two implementers commit in one worktree at once.

## Review Focus

1. **A query that reaches another tenant.** A repository that still takes a raw `Querier`, a job that runs outside
   `forEachTenant`, a single-column foreign key between scoped tables, or a unique index without `tenant_id`.
   Tasks 3, 16 and 17 test each.
2. **A test that passes because the policy does not apply.** A superuser or `BYPASSRLS` connection anywhere in the
   integration suites. Task 1 asserts the role, and Task 17 runs as it.
3. **The migration.** No sealed audit row rewritten, a file step that resumes after a kill at every point, a re-wrap
   that never sets a cookie jar aside, and a revert that restores `0019` exactly. Tasks 3, 20, 22 and 26.
4. **Self-hosted unchanged.** `Host` never read in self-hosted mode, no slug in any output, and the browser e2e green
   on a migrated server. Tasks 5 and 27.
5. **The lease.** No two processes ever holding one user's checkout, a lost lease stopping its instance before
   expiry, and the cap evicting idle instances before it refuses. Tasks 24 and 25.

## Part B — the modules in a tenant, first half

Every task in Parts B and C follows one recipe:

1. The module's repository functions take a `TenantQuerier` first, where they took a `Querier`.
2. Its routes call them with `ctx.tenancy.db(request.tenant)`.
3. Its timers go through `forEachTenant`.
4. Its in-memory keys lead with the tenant id.
5. Every read of `config.publicUrl` becomes `tenantUrl(request.tenant)`.
6. Its integration suite gains a two-tenant case: two tenants made by `TenantDirectory.create`, a hosted-mode
   server, a write in A, and B sees nothing through every route of the module.

Until `0021` there is no policy, so the two-tenant case proves the filters and keys, and Task 17 proves them again
under the policy.
