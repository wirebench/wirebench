# Plan: Wirebench shared workspaces (git-native collaboration)

Spec: `docs/specs/2026-09-13-wirebench-shared-workspaces-design.md` (approved 2026-09-13 with the §16 defaults). Section refs (§n) point at that spec; "workspaces plan" points at `docs/plans/2026-09-11-wirebench-workspaces-plan.md`, "unsaved spec" at `docs/specs/2026-09-13-unsaved-changes-across-sessions-design.md`.
Executors: superpowers:subagent-driven-development (fresh subagent per task, review between tasks). Tick boxes as tasks land. One commit set per task, Conventional Commits, no `Co-Authored-By` trailer, `pnpm check` green before every commit, all three OSes green in CI at every checkpoint.

**Goal:** a workspace can be shared as a git repository (or a synced folder): members join by URL, every save is a commit, Sync pulls/merges/pushes with an in-app conflict resolver, environments travel with the workspace, secret refs are shared while values stay per machine — and the server backend of spec 2 plugs into the same `SyncBackend` interface.
**Architecture:** engine gains the v3 manifest (no per-machine fields), `local.yaml`/`share.yaml` schemas, a tree-root resolver and a path→entity commit-message generator (pure) ← main gains `sync/` (`GitCli` over system git, `GitBackend`/`FolderBackend` behind `SyncBackend`, `SyncService` with a queue, timer and save hooks, a workspace-level watcher) and `WorkspaceService` learns the tree root, share/join/stop/move ← additive `sync.*`/`git.*` channels and events, `share` on the workspace wires ← renderer `useSyncStore`, a status-bar badge and Sync panel, banners, resolver, share/join dialogs, the *Not on this machine* secret state.
**Stack:** unchanged. **No new runtime dependency**: system `git` is found, never bundled; Radix `Dialog` (already a dependency) hosts the Sync panel and the resolver.

## Global constraints (every task inherits)

- Everything in the workspaces plan "Global constraints", v1 §12, spec §12, ADR-0003/0004/0005/0006.
- The renderer never sends a filesystem path. External tree folders and the git executable come from native dialogs in main (`pickFolder`, `pickFile`) or from `findGit`; remotes are validated text (`assertRemoteUrl`). Any new channel with a `path` field is a defect.
- Git runs only through `GitCli.run` (`execFile`, argument arrays, `cwd` = tree, `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=''`, `GIT_SSH_COMMAND` defaulted to `ssh -o BatchMode=yes` when unset, `LC_ALL=C`, `-c core.autocrlf=false -c merge.conflictstyle=merge -c core.hooksPath=<empty dir>`). Subcommands come from the `GIT_SUBCOMMANDS` array; a `-`-prefixed argument where a path or URL is expected is a defect. Never a shell, never a prompt, never hooks.
- The tree (`workspace.yaml`, `environments/`, `projects/`, `.gitattributes`) never contains `local.yaml`, `share.yaml`, `unsaved/`, secrets or history. An external `share.path` inside `<userData>` is refused (`share-path-invalid`).
- Workspace manifest goes to `formatVersion: 3` in T1 and nowhere else; project format is untouched (the REST branch bumps it independently, §14). Deterministic serialisation (`stringifyYaml`, `writeFileAtomic`) for every new file.
- Every user-facing failure is a `WirebenchError` with a code from §5.1/§6 (`git-not-found`, `git-auth-failed`, `git-offline`, `git-remote-refused`, `git-failed`, `git-not-a-repository`, `git-identity-needed`, `sync-conflict`, `sync-uncommitted`, `sync-not-supported`, `share-linked-project-refused`, `share-path-invalid`, `folder-not-empty`, `workspace-already-present`, `secret-missing`) and a message the toast/banner can show as-is.
- The one path a channel may carry is a **tree-relative** path that main itself produced (a conflict list entry) echoed back to `sync.revealTree`; main joins it to the tree and containment-checks it before `shell.showItemInFolder`.
- UI copy says *share*, *sync*, *pull*, *push*, *commit*; never names other tools (`pnpm check:banned-terms`).
- Ask first: a runtime dependency (including a Radix package); bundling git; a YAML-aware merge driver; linked projects in shared workspaces; any network endpoint beyond the user's remote; changing the auto-fetch default.
- Never block workspace open on git: `SyncService.start()` runs after `open()` has returned the snapshot; a failing probe yields `state: 'error'`, not a failed open.

## Order & rationale

```
W0 engine      1 (v3 manifest, local.yaml, share.yaml, tree root) → 2 (commit messages)
W1 main        3 (WorkspaceService: tree root + local state, behaviour-neutral, full e2e green)
               → 4 (workspace watcher) → 5 (GitCli + git.path preference) → 6 (backends + contract suite) → 7 (SyncService)
W2 skeleton    8 (share / join / stop / move in WorkspaceService) → 9 (IPC contract + renderer store)   = pushed together
W3 UI          10 (badge + Sync panel + commands) → 11 (banner + resolver + conflict marks) → 12 (share/join dialogs, picker, move)
               → 13 (secret "Not on this machine") → 14 (Git preferences section)
W4 ship        15 (git e2e, two profiles) → 16 (docs, ADR-0008, changelog, screenshots)
```

- Engine first: the manifest split and the message generator are pure and pin the file contract.
- T3 is the risk reducer: the tree root and `local.yaml` land with **zero behaviour change** for local workspaces and the whole e2e suite green, before any git code exists.
- T5–T7 test against a temporary bare repository over `file://`; no UI yet. The contract suite in T6 runs the same assertions against `GitBackend`, `FolderBackend` and `FakeServerBackend`, so spec 2 inherits it.
- T8 and T9 are the walking skeleton: after T9 a workspace can be shared and joined from the command palette with a placeholder badge; pushed together (ledger note), each `pnpm check` green.
- W3 tasks are independent after T9 and review as separate diffs. W4 proves §13.

## Risks

- **`WorkspaceService` is 66 KB and every wave touches it.** T3 and T8 add methods; T7 adds the sync record. Keep each addition in its own region with a banner comment and extract `share/join/stop/move` into `main/workspace-share.ts` (functions taking the service's private deps as parameters) if T8 pushes the file past 80 KB.
- **Line-level merge on YAML** (§15). The contract test's conflict case is the environment file; request bodies are the realistic case and are covered in the e2e conflict test.
- **Two Electron instances in one e2e test** double memory on the Windows runner. Keep the two-profile tests in one serial file; if flaky, run them under a dedicated Playwright project with `workers: 1`.
- **Git identity on CI runners** is unset; `gitConfigEnv` isolates it per launch so tests neither depend on nor pollute the runner's config.
- **`GIT_CONFIG_NOSYSTEM=1` in e2e** disables system credential helpers — irrelevant for `file://` remotes, but never set it in the app itself.
- **Clone-then-rename on join** — `.joining/` is cleaned at service construction (T8), so a crash mid-clone leaves nothing the picker can trip on.
- **`ProjectWatcher` on the tree root** watches `projects/**` too (recursive `fs.watch`); the predicate filters, but on Linux the per-directory fallback caps depth at 4 — workspace-level files are at depth ≤ 2, so no gap.

## Unresolved questions (bold = proposed default)

1. Sync panel host: **Radix `Dialog` (already a dependency)** rather than adding `@radix-ui/react-popover` for a true status-bar popover — a new runtime dependency is ask-first. Say the word and T10 switches.
2. `SyncBackend` gains `finishMerge()`, `changedPaths()`, `identity()`, `setIdentity()` beyond the §5.1 list: **accept** — the first commits a resolved merge, the others feed commit messages and the identity prompt; spec 2's server backend implements them trivially (server-side commit, server identity).
3. Uncommitted changes found at open (CLI edits, synced folders, moved-in projects) with *Commit on save* on: **committed on open** with a generated message, so the tree is never silently dirty.
4. *Move to workspace…* semantics: **copy into the target, then remove from the source (internal files to the trash) after a confirmation**; the spec's §3.2 wording says "copies" — the command name says move.
5. e2e git-config isolation via `GIT_CONFIG_GLOBAL` + `GIT_CONFIG_NOSYSTEM`: **yes**, on every sync-spec launch.
6. `sync.pull`/`sync.push` default shortcuts: **`Mod+Alt+L` / `Mod+Alt+U`** unless `SPEC_DEFAULT_SHORTCUTS` already binds them; T10 checks.
