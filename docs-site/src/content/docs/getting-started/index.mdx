Wirebench is a desktop client for testing and exploring APIs. It sends SOAP, REST and gRPC requests
from one window, keeps your work as plain files you can review in git, and runs entirely on your
machine: no account, no cloud sync you did not set up, no telemetry.

![The workspace picker Wirebench shows on first launch](/wirebench/docs/images/getting-started/workspace-picker.png)

## What it speaks

| Protocol | Start from | Guide |
| --- | --- | --- |
| SOAP 1.1 and 1.2 | A WSDL (URL, file or pasted), with its imports and includes | [SOAP and WSDL](/wirebench/docs/guides/soap-wsdl/) |
| REST | An OpenAPI or Postman collection, a cURL command, or nothing at all | [REST](/wirebench/docs/guides/rest-client/) |
| gRPC | A `.proto` file, or server reflection | [gRPC](/wirebench/docs/guides/grpc/) |
| WebSocket | A URL, or an AsyncAPI document | [WebSocket](/wirebench/docs/guides/websocket/), [AsyncAPI contracts](/wirebench/docs/guides/asyncapi/) |

A REST response can also be a stream of server-sent events, read in the same response pane. See
[Event streams](/wirebench/docs/guides/rest-client/#event-streams).

## What it does beyond a single request

- **Scripts.** A request can run a typed TypeScript script before it is sent and after its response
  arrives. See [Scripts](/wirebench/docs/guides/scripts/).
- **Sequences.** Saved requests run one after another, passing values from step to step. See
  [Sequences](/wirebench/docs/guides/sequences/).
- **Snapshot regression.** A request keeps a known-good response and lists what changed on each send.
  See [Snapshot regression](/wirebench/docs/guides/snapshot-regression/).
- **Webhooks.** Catch incoming webhooks, send your own, sign and verify them, and assert on the
  webhook a request causes. See [Webhook inbox](/wirebench/docs/guides/webhooks/) and
  [Sending webhooks](/wirebench/docs/guides/sending-webhooks/).
- **CI and agents.** The `wirebench` command runs a project in a pipeline, and `wirebench mcp` serves it
  to a coding agent. See [Run in CI](/wirebench/docs/guides/run-in-ci/) and
  [Agents (MCP)](/wirebench/docs/guides/agents-mcp/).

## How your work is organised

- A **workspace** is the top level. It holds any number of projects, one set of environments shared
  by all of them, and your open tabs. Wirebench keeps it in its own data folder, so there is no
  folder for you to pick or manage.
- A **project** holds what you import or create: interfaces, APIs, requests and their properties.
  On disk it is a folder of small YAML and XML files, so it can be exported, reviewed and kept in git.
- A workspace can be **shared with a team** over git or a synced folder. See
  [Shared workspaces](/wirebench/docs/guides/shared-workspaces/).

## Where to start

1. [Install Wirebench](/wirebench/docs/getting-started/installation/) on macOS, Windows or Linux.
2. Follow the [ten-minute walkthrough](/wirebench/docs/getting-started/walkthrough/): a SOAP request, then
   a REST request.
3. Keep the [command reference](/wirebench/docs/reference/commands/) handy. Everything in Wirebench is a
   command in the palette (<kbd>⌘K</kbd> on macOS, <kbd>Ctrl+K</kbd> on Windows and Linux).
