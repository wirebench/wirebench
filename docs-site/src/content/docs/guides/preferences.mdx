Preferences hold everything that applies across projects — transport defaults, the theme, keyboard
shortcuts — as opposed to a project's own settings, which travel with the project file. Open
**Settings** with <kbd>⌘,</kbd> / <kbd>Ctrl+,</kbd>, the gear at the foot of the activity bar, or the
command palette.

## The Settings page

Settings takes the whole window while it is open, and nothing you had open behind it changes. On the
left are **← Back to app**, a search field, and the sections in five groups; the chosen section is on
the right. **Back to app** or <kbd>Escape</kbd> returns to your work (Escape leaves a text field alone
while it has focus, so it can undo what you were typing).

Every setting is a row: its name, a line saying what it does, and its control on the right. Switches,
segmented controls and drop-downs apply the moment you change them; text and number fields apply when
you press <kbd>Enter</kbd> or move on, and <kbd>Escape</kbd> puts back the previous value.

- **Changed settings** — a row that differs from its default shows a small dot, and a **Reset** link
  appears next to its name when you hover over or tab into it; it puts back just that setting. Sections
  with changes have a dot in the sidebar.
- **Reset a whole section** — the **•••** menu next to the section's title has
  **Reset _section_ to defaults**.
- **Search** — type in the search field (<kbd>⌘F</kbd> / <kbd>Ctrl+F</kbd>) to list every matching
  setting from every section, each labelled with where it lives, for example _Requests › HTTP_. The
  controls in the results work as they do in their section. <kbd>Escape</kbd> clears the search.

## Sections

| Group | Section | What it covers |
| --- | --- | --- |
| General | **Appearance** | Theme (system, light or dark); the editor's font family and size, tab size, line numbers and word wrap; the default request layout (side by side or stacked, split or tabs) |
| | **Behaviour** | Validate before sending, format responses, autosave, confirm before deleting, preview tabs, and how many history entries and HTTP Log rows to keep |
| | **Keyboard shortcuts** | Every command's keybinding, and a way to change it |
| | **Updates** | Whether Wirebench checks GitHub Releases for a new version at launch |
| Requests | **HTTP** | User-Agent, request/response compression, keep-alive vs. `Connection: close`, socket timeout, max connections, whether to offer HTTP/2 (on by default; NTLM and Kerberos always use HTTP/1.1), and the chunking threshold |
| | **REST** | Follow redirects and the maximum redirect chain length, the default `Accept` header, the pretty-print size threshold, and the OAuth2 callback port — all floors a request's own Settings tab can override |
| | **WSDL** | Definition caching and compression, strict schema handling, and defaults for generated requests (sample values, type comments, optional elements, pretty print) |
| | **WS-I** | WS-I Basic Profile validation: the profile (currently BP1.1 only) and whether its report is verbose |
| Network | **Proxy** | No proxy / system proxy / manual, with host, port, username, password, and a comma-separated exclude list (hosts, `*.wildcards`, CIDR blocks, `localhost`) |
| | **SSL / TLS** | Minimum TLS version, a CA bundle to trust in addition to the system store, the default client keystore, how many days ahead certificate expiry warnings start, and why there's no global "trust all certificates" switch |
| Workspace | **Git** | The `git` executable Wirebench runs for shared workspaces: auto-detected, or located with a picker |
| | **Mock services** | Whether a [mock](/wirebench/docs/guides/mock-services/) listens on every network interface instead of this machine only |
| | **Terminal** | The terminal's font, size, line height and colour scheme; whether a multi-line paste into an SSH terminal asks first, whether a selection is copied to the clipboard as soon as it is made, and the shell a local terminal runs |
| | **Secrets** | How long a value fetched from a secret manager stays in memory |
| Account | **Accounts** | Every server you're known to, sign out or remove one, add another, and whether the status bar shows who you're signed in as |
| | **Devices & tokens** | CI tokens for the open server workspace |

<Aside type="tip" title="A request's own settings win">
REST and WSDL preferences are defaults, not locks. A request or project that sets its own
redirect policy, `Accept` header, or generation option always overrides what's here.
</Aside>

### Proxy and TLS are live

Proxy and SSL preferences aren't just stored for later — they're read on every send. A proxy
password goes through the same secret store as any other credential (see
[Secrets](/wirebench/docs/guides/secrets/)); the CA bundle path is set only through **Browse…**, which
runs a native file picker, since Wirebench never trusts a path the interface alone claims.

On a managed machine, your organization can lock the proxy, the minimum TLS version, the CA bundle and
update checks. Locked settings are read-only and marked **Managed**; see
[Managed preferences](/wirebench/docs/guides/managed-preferences/).

### Locating git

Settings → Git only ever asks Wirebench to detect, locate, or clear the git executable — it
never lets you type a path directly. **Detect** looks for `git` where it would normally be found;
if that fails, or you want a different one, **Browse…** opens a native picker.

### Accounts

Settings → Accounts lists every server Wirebench knows about, each with its email, display
name, device name, and whether it's currently signed in. Per row, **Sign out** ends that session
without forgetting the server, and **Remove** signs out and forgets it; **Add server…** opens the
same sign-in dialog as the status bar item, to add another. See
[Sign in to a server](/wirebench/docs/guides/shared-workspaces/#sign-in-to-a-server) for what signing
in does and when Wirebench asks for it.

**Show sign-in in the status bar** (on by default) controls only whether the status bar's account
item appears once a server is known — the list of servers itself isn't a preference; it lives
wherever Wirebench keeps accounts, not in this preferences document.

### Secrets

**Secret source cache (seconds)** is `secrets.sourceCacheSeconds`: how long a value fetched from an
external secret manager stays in memory. The default is 300 (5 minutes), and the range is 0 to 3600.
With 0, the value is fetched on every send. Values are never written to disk. A change to the
workspace's secret mapping empties the cache too, and so does the **Clear Secret Source Cache**
command. See [Secrets from external managers](/wirebench/docs/guides/secrets/#secrets-from-external-managers).

### Terminal

**Appearance** sets how every terminal looks. **Font family** is `terminal.fontFamily`: pick one of the
monospaced fonts installed on this machine, or **App default** for the app's own monospace font. Where the
platform cannot list fonts, it is a text field instead. The chosen family is tried first, and the app's
font fills in for any character it lacks. **Font size** is `terminal.fontSize` (13 px by default, 6 to
72), and **Line height** is `terminal.lineHeight`, a multiple of the font size from 1 to 2 (1 by
default). **Colour scheme** is `terminal.colorScheme`: **Follow app theme** (the default, `app`) uses the
app's light or dark colours, and the built-in schemes are **Red background**, **Amber background** and
**Green background** (dark, with a tinted background to tell environments apart) and the open palettes
**Solarized Dark**, **Solarized Light**, **Dracula**, **Nord**, **Gruvbox Dark**, **One Dark** and
**Tomorrow Night**. A host or group can set its own scheme and size in `hosts.yaml`; see
[Hosts and terminals](/wirebench/docs/guides/hosts-and-terminals/#terminal-colours-and-font-size). Open
terminals change as soon as a setting does.

**Highlight output** is `terminal.highlightOutput` and is on by default: in SSH and local terminals,
error words (`error`, `fail`, `failed`, `fatal`, `denied`, `refused` and a few more) show in the scheme's
red, warning words (`warn`, `warning`, `deprecated`) in its yellow, `info`, `notice` and `debug` in its
blue, and IPv4 and IPv6 addresses in its cyan. Only whole words count, so `stderr` and `error_log` stay
plain. The colours are drawn over the output, which is never changed: copying, find and session logs see
the text as it arrived. Text a program coloured itself keeps its own colours, and full-screen programs such
as editors are left alone. The full list of words is under the switch.

**Confirm multi-line paste** is `terminal.confirmMultilinePaste` and is on by default: pasting text
with more than one line into an SSH terminal first shows its opening lines, because a pasted script
runs line by line. A single trailing newline does not count as a second line. Ticking **Don't ask
again** in that prompt turns the preference off. **Copy on select** is `terminal.copyOnSelect` and is
off by default.

**Suggest snippets** is `terminal.snippetSuggestions` and is on by default: typing the start of a snippet's
first line in an SSH terminal shows the rest of it dimmed after the cursor, and **Tab** completes it without
pressing Enter.

**Confirm closing live sessions** is `terminal.confirmCloseSessions` and is on by default: closing tabs
that hold a connected SSH, Telnet or serial session, or a running local terminal, asks once for the whole
batch, since closing ends the connection and whatever runs in it. Ticking **Don't ask again** in that
question turns this off.

**Reconnect dropped sessions** is `terminal.autoReconnect` and is on by default. When the network drops
a session (a reset, a timeout, a jump host's connection ending), the tab keeps its scrollback and tries
again after 1, 2, 4, 8 and 16 seconds, then every 30 seconds, showing the attempt and a countdown with
**Reconnect now** and **Stop** on the connection screen. Waking from sleep, or the network coming back, tries at once. A shell that
exited, a sign-in failure or a changed host key never reconnects: the connection screen shows the reason
or the host-key prompt. **Reconnect attempts** is `terminal.reconnectAttempts`: how many tries before the tab
stops and offers **Reconnect**. The default is 10, and the range is 1 to 100.

**Session logs size limit** is `terminal.sessionLogMaxMb`: how much room all
[session logs](/wirebench/docs/guides/hosts-and-terminals/#session-logs) on this machine may take together, in
megabytes. Past it the oldest logs are deleted first. The default is 500, and the range is 10 to 100000.
**Keep raw output** is `terminal.sessionLogRaw` and is off by default: when on, each log also keeps the
stream as the terminal received it, colours and escape sequences included, beside the plain text.

**Local shell** is `terminal.localShell` and is empty by default: a local terminal then runs your login
shell (`$SHELL`) on macOS and Linux, and PowerShell 7 or else Windows PowerShell on Windows. A path or
program name (`/bin/bash`, `cmd.exe`, `wsl.exe`) runs that instead; on macOS and Linux it starts as a
login shell (`-l`). A change applies to the next local terminal you open.

## Theme

Settings → Appearance → **Theme** switches between **System** (follow the operating system), **Light**, and
**Dark**.

## Rebinding shortcuts

<Steps>

1. Open Settings → **Keyboard shortcuts**. Every command is listed with its category, its default
   binding, and its current one.
2. Click a row's shortcut cell to start recording, then press the key combination you want.
   <kbd>Escape</kbd> cancels without changing anything; <kbd>Backspace</kbd> leaves the command
   unbound.
3. If the combination isn't safe to rebind, the row shows why instead of accepting it.
4. **Reset all** restores every command to its default binding.

</Steps>

![Settings open on Keyboard shortcuts, listing commands with their category and key binding](/wirebench/docs/images/preferences/shortcuts.png)

A rebind takes effect immediately and is remembered across restarts. Some defaults you'll see
listed: <kbd>⌘K</kbd> / <kbd>Ctrl+K</kbd> for the command palette (also <kbd>⌘⇧P</kbd> /
<kbd>Ctrl+Shift+P</kbd>), <kbd>⌘P</kbd> / <kbd>Ctrl+P</kbd> for quick open, <kbd>⌘I</kbd> /
<kbd>Ctrl+I</kbd> for Import, <kbd>⌘S</kbd> / <kbd>Ctrl+S</kbd> to save, <kbd>⌘⏎</kbd> /
<kbd>Ctrl+Enter</kbd> to send, and <kbd>⌘,</kbd> / <kbd>Ctrl+,</kbd> for Settings itself. The
full, generated list is in [Commands and shortcuts](/wirebench/docs/reference/commands/).

## Layout

The window is split into panels — the activity bar, the sidebar (Explorer, Environments, WSS,
and so on), the editor area, and the console (History, HTTP Log, Problems) — each with a handle
between it and its neighbor.

<Steps>

1. **Drag** a handle to resize the panel next to it. Dragging past its minimum size collapses the
   panel instead of shrinking it further.
2. **Double-click** a handle to collapse the panel, or to restore it to the size it had before —
   the handle's own label switches between "Resize" and "Show" so you can tell which it will do.
3. With a panel collapsed, click its icon in the activity bar (for the sidebar) to reopen it at
   its previous size.

</Steps>

Collapsing the console never takes the editor area down with it, and the reverse holds too — each
panel's collapse is independent.
